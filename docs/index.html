Feature definitions

What the project means by local-first AI.

These are not marketing buckets. Each feature maps to a visible app surface and a native implementation area in the repository.

01

Local-first chat workspace

A React Native chat shell for private sessions, model selection, work folders, saved display settings, and conversation state.

Surface
Chat, settings, sessions, folders
Code anchors
src/screens, src/state, src/native/AIEngine.ts
02

Native model runtime

Device runtimes are handled by platform modules instead of a remote-only chat API, so model loading and status stay close to the user.

Surface
Runtime status, model lifecycle, generated responses
Code anchors
ModelRuntimeManager, GemmaManager, iOS model clients
03

Device-side retrieval

Context indexing, embeddings, vector storage, and query routing are designed to work on user data without making cloud storage a requirement.

Surface
Private context, semantic search, background indexing
Code anchors
MemoryIndexer, EmbedManager, VectorDBHelper
04

Multimodal inputs

Text, files, images, and richer attachments share one typed request path so the app can grow without replacing the bridge.

Surface
Attachment-aware prompts and vision request scaffolding
Code anchors
MultimodalRequest, VisionManager, FilePicker
05

Web preview target

The Vite and React Native Web target keeps UI iteration fast while preserving the cross-platform component model.

Surface
Browser preview for frontend-only development
Code anchors
index.web.tsx, vite.config.ts, src/web
06

Dynamic Island pets

Five tiny pixel companions represent background activity in the iOS island UI: Orbit, Stacky, Signal, Luma, and Flux.

Generating locally Dynamic Island status with pet motion

The site uses the same 7-by-7 pixel matrices and color families as the iOS feature, tuned into the dark grid visual system instead of dropping in unrelated illustration.
